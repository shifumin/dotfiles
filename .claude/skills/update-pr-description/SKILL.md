# PR 説明文の更新

PR の本文を、いまのコードと事実が合い、コードを読まない人にも一読で分かる文章にする。

## 手順

1. 本文とコミットを取得し、本文は scratchpad にファイルとして保存する

   ```bash
   gh pr view <number> --json title,body,commits,baseRefName,headRefOid
   gh pr diff <number>
   ```

2. 本文を diff と照らし、事実と食い違う箇所、抜けている変更、決着済みの「検討中」を洗い出す
3. 書き直す
   - 構成は、リポジトリの PR テンプレートや PR 説明文のスキルがあればそれに従う
   - コードを読まない人が読む前提で書く。クラス名・メソッド名・内部の処理名は、利用者や運用者から見た出来事に言い換える
   - 冗長な説明、感情を込めた表現、テストの実行結果は書かない。頼まれていない節を足さない
   - 出力（CSV の列、通知文など）が変わるときは、変更前と変更後を表で示す
4. 変わる箇所だけ before/after で見せ、承認を取る
5. 更新の直前に本文を取り直し、手順1から人の編集が入っていれば、その差分を残して自分の変更だけを当てる
6. `gh pr edit <number> --body-file <file>` で更新し、`gh pr view --json body` で読み返して確かめる。末尾の改行の差は無視してよい
