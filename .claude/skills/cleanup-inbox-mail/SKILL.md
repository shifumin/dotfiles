# Cleanup Inbox

| カテゴリ | 引数 | 操作 |
|---------|------|------|
| 迷惑メール（スパム、spam） | `spam` | ゴミ箱へ（復元できるようtrash止まり） |
| 購入（purchases） | `purchases` | 未読をアーカイブ＆既読化 |
| ソーシャル（SNS、social） | `social` | 同上 |
| プロモーション（プロモ、広告） | `promotions` | 同上 |

既読は「自分で開いた＝意図あり」なので残し、未読だけを処理する。

**対象カテゴリ**: 発話でカテゴリ名に触れていれば、触れたものだけ。触れていなければ全4つ。対象外カテゴリは表示・確認・報告のどこにも出さない。

**件数モード**: 整理を命じる動詞（整理して／片付けて／アーカイブして／削除して／実行して 等）もskill名の指名も無い発話（「何通溜まってる？」「整理する前に何通あるか確認したい」）は件数モード。迷ったら件数モード（誤削除より聞き直しの方が安全）。

## Step 1: 取得して表示

```bash
python3 ~/.claude/skills/cleanup-inbox-mail/scripts/inbox.py fetch <対象カテゴリの引数...>
```

出力のMarkdown（見出し・全件テーブル・0件カテゴリの「対象のメールはありません」）を **加工せずそのまま** 表示する。テーブルの列は `# | 送信者 | 件名 | 日時 | リンク`。リンク列はGmailでそのメールを開くパーマネントリンクで、迷惑メールは処理後に入るゴミ箱用の `#trash/<messageId>`、アーカイブ対象は `#all/<messageId>`（`https://mail.google.com/mail/u/0/#<view>/<messageId>`）。リンクを削ったり別形式に直したりしない。全件を見せるのは、ユーザーが何を消すか目視確認するため（「〜等」での省略禁止）。末尾の `COUNTS` 行は表示しない。続けて1行だけ添える:

| 状況 | 添える1行 |
|------|----------|
| 対象が全部0件 | テーブルも出さず「受信トレイは綺麗だよ！対象のメールはなかったよ。」のみで終了 |
| 件数モード | 「合計 N件（迷惑 N / 購入 N / ソーシャル N / プロモ N）が溜まってるよ。」（対象カテゴリのみ、0件も数字で書く）で終了 |
| 通常 | 「迷惑メール N件をゴミ箱、購入 N件・プロモーション N件をアーカイブして既読化するよ。実行していい？」（0件カテゴリは省略） |

件名から状況を推測した注意書きは書かない（販促メールは件名で手続き中や重要を装う）。伝えるべきか迷うメールは `gws gmail users messages get --params '{"userId":"me","id":"<id>","format":"minimal"}'` の `snippet` を見てから書く。

## Step 2: 実行と報告

明示的な同意（y / はい / 実行して 等）を得てから:

```bash
python3 ~/.claude/skills/cleanup-inbox-mail/scripts/inbox.py apply
```

Step 1で保存したIDだけを処理し、再検索で残っていないか確かめて完了報告を出力する（batchModifyは成功しても何も返さないため、読み戻しで判定する）。出力をそのまま表示する。失敗行があればその旨を一言添える。

## 認証エラー時

401 `Failed to get token` や 403 insufficientPermissions が出たら、`gmail` スキルの「認証エラー時」の手順（`gws auth logout` → フルスコープで `gws auth login`）に従う。
