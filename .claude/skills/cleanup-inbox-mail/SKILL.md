# Cleanup Inbox

| カテゴリ | 引数 | 操作 |
|---------|------|------|
| 迷惑メール（スパム、spam） | `spam` | ゴミ箱へ（復元できるよう trash 止まり） |
| 購入（purchases） | `purchases` | 未読をアーカイブ＆既読化 |
| ソーシャル（SNS、social） | `social` | 同上 |
| プロモーション（プロモ、広告） | `promotions` | 同上 |

既読は意図して開いたものとして残し、未読だけを処理する。

- **対象カテゴリ**: 発話でカテゴリ名に触れていれば該当分のみ、触れていなければ全4つ。対象外カテゴリは表示・確認・報告のどこにも出さない
- **件数モード**: 整理を指示する動詞（整理して・片付けて・アーカイブして・削除して・実行して 等）もスキル名の指名もない発話（「何通溜まってる？」「整理前に確認したい」等）は件数モード。迷ったら件数モードを選ぶ（安全側）

`<base>` はこの `SKILL.md` があるディレクトリの絶対パス。

## Step 1: 取得して表示

```bash
python3 "<base>/scripts/inbox.py" fetch <対象カテゴリの引数...>
```

出力の Markdown（見出し・全件テーブル・リンク列・0件表記・上限到達注記）を **加工・省略せずそのまま** 表示する（全件表示は削除対象の目視確認のため。リンク列の改変・削除や「〜等」での省略をしない）。末尾の `COUNTS` 行だけは表示しない。続けて上から順に該当する1行を添える:

| 状況 | 添える内容 |
|------|-----------|
| 対象がすべて0件 | テーブルも出さず、対象メールが0件だった旨のみ伝えて終了 |
| 件数モード | 合計件数と対象カテゴリの内訳（0件も含む）を伝えて終了（確認質問は出さない） |
| 通常モード | 0件以外のカテゴリについて操作内容（迷惑メールはゴミ箱、その他はアーカイブ＆既読化）と件数を示し、実行可否を確認する |

件名から状況を推測した注意書きは書かない（販促メールは件名で手続き中や重要を装う）。伝えるべきか迷うメールは `gws gmail users messages get --params '{"userId":"me","id":"<id>","format":"minimal"}'` の `snippet` を確認してから書く。

## Step 2: 実行と報告

明示的な同意（`y` / はい / 実行して 等）を得てから実行する:

```bash
python3 "<base>/scripts/inbox.py" apply
```

Step 1 で保存した ID だけを処理し、再検索で残存がないか確かめて完了報告を出力する（`batchModify` は成功時に空を返すため読み戻しで判定する）。出力をそのまま表示し、失敗行（exit 1）があれば未処理 ID が残っている旨と再取得してやり直せる旨を添える。

## 認証エラー時

401 `Failed to get token` や 403 `insufficientPermissions` が出たら、`gmail` スキルの「認証エラー時」手順に従う。
