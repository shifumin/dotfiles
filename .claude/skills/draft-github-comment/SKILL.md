# GitHub コメントの作成

本人が自分で書いたと読める文面を作り、承認を取ってから投稿する。文体は毎回、本人の過去のコメントから取る。
本人の文体は相手によって変わることが多く、固定の規則には書けないため。

## 手順

### 1. 投稿先を決める

| 返す相手 | 投稿先 |
|----------|--------|
| 行コメント（レビュースレッド） | そのスレッドへの返信 |
| レビュー本文の中の指摘（差分の外の指摘、Nitpick など、行コメントになっていないもの） | PR へのコメント。冒頭で指摘の見出しを引用し、どの指摘への返信かを示す |
| PR・Issue 全体 | PR・Issue へのコメント |

### 2. 投稿先を読む

スレッドなら全体を、PR へのコメントなら関係する前後のコメントを読む。相手が使っている呼び名（機能名、クラス名、チケット）を控え、文面でもその表記に揃える。

### 3. 本人の過去のコメントを読む

本人の login は毎回取る（`gh api user --jq .login`）。スキルには書かない。

5〜10件読む。相手の種類（人か bot か）と、返信の種類（対応した、見送る、質問に答える）が同じものを優先する。次の順で探し、足りなければ広げる。

- 同じ PR の本人のコメント
- 同じ相手への返信（人なら同じレビュアー、bot なら同じ bot）
- 本人の最近の PR の返信

```bash
REPO="<owner>/<repo>" LOGIN="<login>" bash <<'SCRIPT'
for n in $(gh pr list --repo "$REPO" --author @me --state all --limit 15 --json number --jq '.[].number'); do
  gh api "repos/$REPO/pulls/$n/comments" \
    --jq ".[] | select(.user.login==\"$LOGIN\" and .in_reply_to_id!=null) | \"#$n \" + .html_url + \"\n\" + .body + \"\n----\""
  gh api "repos/$REPO/issues/$n/comments" \
    --jq ".[] | select(.user.login==\"$LOGIN\") | \"#$n \" + .html_url + \"\n\" + .body + \"\n----\""
done
SCRIPT
```

### 4. 文体を取り出す

相手の種類ごとに次を取り出す。人には短く砕けた返信、bot には理由を箇条書きにした丁寧な返信、のように分かれていることが多い。

- 書き出しと締め（お礼の有無、定型の言い回し）
- 絵文字
- コミットの示し方
- 長さと構成（結論が先か、理由をどこまで書くか）

本人が使っていない言い回し（例:「おっしゃるとおりです」）は使わない。

### 5. 書く

手順4の文体に、次の共通ルールを重ねる。

- 文末に「。」を付けない。文を区切るときは改行する
- 対応したコミットは、短い SHA のリンクで示す（`[abc1234](https://github.com/<owner>/<repo>/pull/<n>/commits/<sha>)`）。push 前ならリンクの場所を空けておき、push 後に差し替える
- 見送るときは、根拠（コード、仕様、データ）を添えて理由を書く
- 指摘を受けて、本人の以前のコメントの誤りが分かったときは、一言触れる
- 平易に書き、依頼にない話題を足さない

### 6. 見せて承認を取る

文面をチャットに出す。文体を取ったコメントを1〜2件、リンクで添える。

### 7. 投稿して読み返す

OK をもらってから投稿する。本文はファイルに書き、`-F body=@<file>` で渡す（改行やバッククォートが壊れないように）。

```bash
# スレッドへの返信
gh api repos/<owner>/<repo>/pulls/<n>/comments/<comment_id>/replies -F body=@<file>
# PR・Issue へのコメント
gh api repos/<owner>/<repo>/issues/<n>/comments -F body=@<file>
```

投稿後に読み返し、狙ったスレッドや PR に付いたか（`in_reply_to_id`、`html_url`）を確かめる。

resolve はこのスキルでは行わない。必要なら review-pr-comments の規則に従う。
