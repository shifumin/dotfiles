# auto memory の棚卸し

auto memory を、**ユーザーの合意を取りながら**整理する。純正 `consolidate-memory` は重複統合とリンク切れ検出までを自己判断で実行するが、進捗系の記述が現実と乖離しているかまでは見ない。このskillはそこを置き換え、不可逆な削除を `_archive/` 退避に差し替える。

## 前提知識

- 毎セッション読まれるのは **MEMORY.md のみ**（先頭200行 or 25KB の早い方）。超過分は黙って捨てられる
- トピックファイルは起動時に読まれない。**MEMORY.md のフック1行が唯一の入口**。したがって棚卸しの主対象は MEMORY.md
- `~/.claude/projects/` はgit管理外。**誤削除は復旧できない**
- 本文の `[[name]]` はファイル名ではなく frontmatter の `name:` を指す

## 設計原則

1. **目次を正確で短く保つのが目的**。件数を減らすことではない
2. **削除しない**。廃止は `_archive/` へ `mv`（トピックファイルは起動時に読まれないので退避コストはゼロ）

## 承認レベル

全部聞くと苦痛、全部黙ってやると事故る。

| 操作 | 承認 | 理由 |
|:--|:--|:--|
| 目次の圧縮（詳細をトピックファイルへ移動） | 不要（事後報告） | 情報が失われない |
| 事実の修正（実体確認・gh等で検証済みのもの） | 不要（事後報告） | 根拠が客観的 |
| `name:` をファイル名にそろえ `[[ ]]` を張り替える | 不要（事後報告） | 機械的で情報が失われない |
| `_archive/` への退避 | カテゴリ単位で一括確認 | 可逆 |
| ファイルの統合・本文の削除・書き換え | **必須** | 不可逆で内容が失われる |
| グローバル指示書（dotfiles）への昇格 | **必須** | PUBLICで仕事端末へ波及する |

## Phase 0 — バックアップ

memoryディレクトリを特定し、実行前にscratchpadへバックアップする（ホームディレクトリは汚さない）。特定に失敗したらユーザーにパスを確認する。**推測で進めない。**

scratchpad のパスは環境変数に無い。システムプロンプトの「Scratchpad directory」を `SP` に書き写す（空のままだとバックアップ先が `/` になって失敗する）。memory ディレクトリ名は、リポジトリの絶対パスの `/` と `.` を `-` に置き換えたもの。

```bash
SP="<システムプロンプトの Scratchpad directory>"
MEM_DIR="$HOME/.claude/projects/$( (git rev-parse --show-toplevel 2>/dev/null || pwd) | sed 's#[/.]#-#g')/memory"
test -d "$MEM_DIR" && test -d "$SP" && cp -r "$MEM_DIR" "$SP/memory-backup-$(date +%Y%m%d-%H%M%S)" && echo "backup ok: $MEM_DIR"
cat "$MEM_DIR/.inventory-state.md" 2>/dev/null
```

`.inventory-state.md`（Phase 6 で書く）があれば、前回の実行日と「解除条件つきで見送った項目」を読む。見送り項目は Phase 2 で最優先に解除条件を確かめる。

## Phase 1 — 実測

数字を出す。印象で語らない。

```bash
cd "$MEM_DIR"
echo "MEMORY.md: $(wc -l < MEMORY.md) 行 / $(wc -c < MEMORY.md) bytes"
awk '/^  type:/{print $(2)}' *.md | sort | uniq -c | sort -rn
grep -L 'modified:' *.md
bash <<'SCRIPT'
echo "--- 更新日 type サイズ ファイル"
for f in *.md; do
  [ "$f" = MEMORY.md ] && continue
  m=$(grep -m1 'modified:' "$f" | awk '{print $(2)}' | cut -c1-10)
  t=$(awk '/^  type:/{print $(2)}' "$f")
  echo "$m $t $(wc -c < "$f" | tr -d ' ') $f"
done | sort
for f in *.md; do
  [ "$f" = MEMORY.md ] && continue
  grep -q "($f)" MEMORY.md || echo "孤児: $f"
  n=$(awk '/^name:/{print $(2); exit}' "$f")
  [ "$n" = "${f%.md}" ] || echo "name不一致: $f ($n)"
done
grep -o '](\([a-z0-9_.-]*\.md\))' MEMORY.md | sed 's/](//;s/)//' | while read -r p; do
  [ -f "$p" ] || echo "リンク切れ: $p"
done
grep -oh '\[\[[a-z0-9_-]*\]\]' *.md | sort -u | sed 's/^\[\[//;s/\]\]$//' | while read -r n; do
  [ -f "$n.md" ] || echo "未解決 [[ ]]: $n"
done
grep -n '^- \[' MEMORY.md | while IFS= read -r l; do
  n=$(printf '%s' "$l" | wc -m | tr -d ' ')
  [ "$n" -gt 150 ] && echo "$n 字: $(printf '%s' "$l" | cut -c1-50)"
done
SCRIPT
```

出すもの: MEMORY.mdの行数・バイト数（200行/25KBに対する使用率）、ファイル件数、`type` 分布、`modified` が無いファイル、孤児ファイル、`name:` とファイル名の不一致、リンク切れ、未解決の `[[name]]`、150字超のフック行、本文が数行しかない薄いファイル。

`[[ ]]` の検査はファイル名で解決を見る。`name:` がファイル名とずれていると、正しいリンクも未解決に出る（2026-11-21に41件中半数がずれていた）。Phase 5 で `name:` をファイル名にそろえれば両方の解決規則が一致する。日付やskill名など memory 以外の `[[ ]]`（例: `[[2026-08-29]]`）は未解決に出て当然なので除外して読む。

> zshでは `for...done` が parse error になる。ループは必ず `bash <<'SCRIPT'` で包む。
>
> awk のフィールドは `$(2)` と書く。slash command として起動されると本文中の「ドル記号＋数字1桁」が引数で置換されるため。
>
> リンクの正規表現には `_` `-` `.` を全部含める。ファイル名は snake_case と kebab-case が混在しており、どれかが欠けるとマッチ漏れで「リンク切れ 0件」が常に出る。

## Phase 2 — 鮮度検証

**ここが本体。** 記憶の内容を鵜呑みにせず、外部の事実と突き合わせる。まず全トピックファイルの本文を読む（出力が大きいとファイルに退避されるので、その場合は Read で読む）:

```bash
cd "$MEM_DIR" && awk 'FNR==1{print "=== " FILENAME; fm=0} /^---$/{fm++; next} fm>=2{print}' $(ls *.md | grep -v '^MEMORY.md$')
```

- **ファイル・ディレクトリ・関数・フラグ名への言及** → `ls` / `find` / `grep` で実体がまだ存在するか確認する。**参照先が消えている記憶は最悪**（存在しないドキュメントを毎回読みに行かせる）
- **PR / issue 番号** → `gh pr view <n> --json state,mergedAt` / `gh issue view <n> --json state`
- **「◯◯までは注意」「未定」「マージ前に実施」型の状態記述** → 解除・決着していないか最優先で確認する。正本ノートがあればそちらを読む。目次に残ると毎セッション誤った前提を与える
- **相対日付**（「来週」「今月中」）→ 絶対日付に変換できるか
- **指示書との重複・矛盾** → グローバル `AGENTS.md` / `CLAUDE.md` / `.claude/rules/` / プロジェクトの指示書・skillに同じことが書いてないか。矛盾していたら**指示書側が間違っている可能性**を疑う

検証できなかったものは「未検証」として提案に明記する。**検証済みと混ぜない。**

## Phase 3 — 提案の組み立て

**判断の性質ごと**にカテゴリへまとめる。ファイル単位で並べない。

- **事実誤り** — 検証で誤りが確定したもの（承認不要だが必ず提示する）
- **役割を終えた記録** — 完了した作業、決着したissue、期日が過ぎたもの → 退避候補
- **近接クラスタ** — 同じ話題の複数ファイル → 統合候補
- **目次の肥大** — 150字を超えるフック行 → 圧縮候補
- **再取得可能** — コード・git履歴・issue・指示書・skillを見れば分かるだけのもの → 退避候補
- **rules向き** — 特定プロジェクトに依らず、どのプロジェクトでも踏むもの → 昇格候補。Claude Code と Codex 共通ならdotfilesの `AGENTS.md`、Claude固有なら `.claude/rules/`。既存の行が同じことを言っていれば昇格しない
- **中身が薄い** — 本文が数行で、単独ファイルである必要が無いもの → 他へ畳む候補

**再取得可能かの線引き**: 引き直せるもの（ディレクトリ構成、依存関係、過去の修正内容）は削る。引き直せないもの（ユーザーが明言した好み、判断に至った経緯、実測して初めて分かった罠）は残す。

`project` には「進行中の状態」と「恒久的な知見」が混ざりやすい。前者は決着すれば不要、後者は1年後も有効。恒久的な技術知見は `project` のままでよい（`reference` は外部リソースへのポインタを指す型なので、そこへ移すのは定義に反する）。

## Phase 4 — 合意（AskUserQuestion）

**1ラウンド最大4問**、カテゴリごとに1問、選択肢2〜4個。ファイル単位で聞くと4問の上限に収まらない。選択肢は「一括で実行」「個別に見る」「やらない」が基本で、**推奨を先頭に置いて `(Recommended)` を付ける**（推奨が無いと、ユーザーが「おすすめは？」と聞き返す1往復が増える）。一部だけ推奨なら「推奨のN件だけ実行」を選択肢にする。`description` に**対象件数と代表的なファイル名**を書く。ダイアログではラベルしか見えないため、判断材料は description に寄せる。

質問の前に、そのラウンドで扱うカテゴリの根拠をチャット本文に簡潔に書く。**ダイアログだけで判断させない。** カテゴリが4個を超える場合は影響の大きい順にラウンドを分ける。目次に関わるものが最優先。「個別に見る」が選ばれたカテゴリは次のラウンドで内訳と1件ずつの推奨を提示して再度問う。カテゴリをまたいで「まとめて全部やっていいか」と一問で聞かない（判断の粒度が潰れる）。

承認不要の操作は質問に含めない。最初のラウンドの前に、何をどう直すかをチャット本文で予告するだけにする。

**全ラウンドの合意が出そろうまで Phase 5 に入らない。** 途中で反映を始めると、後のラウンドで退避が決まるたびに目次を書き直すことになる。

## Phase 5 — 反映

合意された範囲のみ、承認レベル表に従って実行する。

**実行順**: 事実の修正 → 統合・退避 → `name:` の統一と `[[ ]]` の張り替え → 目次の書き直し。目次は最後に1回だけ書き直す。

**退避**（`rm` は使わない。このマシンの `rm` は確認プロンプトが出て、Bashツールでは exit 0 のまま削除されない）:

```bash
mkdir -p "$MEM_DIR/_archive"
mv "$MEM_DIR/<file>.md" "$MEM_DIR/_archive/"
```

退避の前に、**そのファイルに残っている恒久的な教訓を生き残る側へ畳んでおく**。記録が役目を終えていても、そこで学んだことは残ることがある。退避したら MEMORY.md から該当行を削除し、ほかのファイルからの `[[name]]` を吸収先へ張り替える（吸収先が無ければ外す）。

**統合**: 内容が厚い側のパスを残し、薄い側を見出し付きの節として末尾に足してから退避する。

**本文の一部だけ削る場合**: 削る部分を `_archive/<name>_log_<date>.md` として切り出してから本体を書き直す。捨てない。

**相対日付の変換**: 「来週」「マージ後」を絶対日付に書き換える。基準が不明で書き換えられない場合はレポートに明記する。

**昇格**: dotfiles はリポジトリ側のパスを編集する（`~/.claude/` 経由のsymlinkはWrite/Editが拒否する）。`AGENTS.md` を変えたら `.codex/build-agents.sh` を流す。commitは編集したファイルだけを明示ステージする（`.claude/settings.json` は auto mode が個人情報を書き足すので巻き込まない）。昇格したmemoryは退避する。

**目次の圧縮**: 1件1行、150字以内、`- [Title](file.md) — 一行フック`。削った詳細は必ずトピックファイル側へ移す。

フックは「何が書いてあるか」ではなく「**どういう時に開くべきか**」を書く。読み手はこの1行だけを見てファイルを開くか決める。近い話題が並ぶときは**発動条件で書き分ける**（「実行する前に」「実行した後にCIが落ちたら」）。内容を要約すると似た話題は似たフックになり、取り違える。

項目が30件を超えたら、開く場面ごとの見出し（`## 環境・ツール`、`## PR・レビュー` など）で束ねる。

削るだけでなく、**新しく重要になったものを目次に足す**。目次に無いトピックファイルは永久に開かれない。

**書き込み時の注意**: noclobberが有効なので `>` は既存ファイルへの書き込みに失敗し、**中身は古いまま残る**。MEMORY.mdの書き直しは `>|` を使うか、pythonで読み書きする。

**上限チェック**: 書き終えたらMEMORY.mdを再計測し、200行/25KBに収まっているか確認する。Phase 1 の検査をもう一度流す。

## Phase 6 — 記録と報告

`$MEM_DIR/.inventory-state.md` を書き直す（`>|` か Write ツールで）。次回の棚卸しが前回の見送りを引き継ぐための記録で、ファイル名がドットで始まるため `*.md` の検査や目次の対象にならない。

```markdown
最終実行: YYYY-MM-DD
MEMORY.md: <行数> 行 / <バイト数> bytes

## 解除条件つきで見送った項目
- <file>.md — <解除条件>（例: PROJ-1234 がマージされたら退避する）
```

チャットで報告するもの:

- 触ったファイル数と操作の内訳（修正 / 圧縮 / 退避 / 統合 / 昇格）
- MEMORY.md の **before / after**（行数・バイト数・使用率）
- **合意が得られず見送った項目**を明示する。黙って落とさない。解除条件があるものは `.inventory-state.md` にも書く
- 未検証のまま残した項目
- バックアップの場所

## 実行頻度

- **主: イベント駆動** — PRマージ / issueクローズ / ファイル移動の時に、該当する記憶をその場で直す。「◯◯まで注意」型はここで消えるのが理想
- **従: 月1回、または新規・更新が15件たまったら**（前回の実行日は `.inventory-state.md` を見る）
- **随時: MEMORY.mdが15KB（上限の6割）を超えたら** — 件数に関係なく実行

従と随時の条件は、SessionStart フック `.claude/hooks/memory-inventory-reminder.sh` が起動時に判定して知らせる。月1回のほうは、件数が少ないプロジェクトで鳴り続けないように「30日 かつ 15件」に絞っている。

毎日は過剰。書き込みの無い日にかけると同じ内容が繰り返し再圧縮され、**具体的で再導出しにくい記述から先に失われる**。
