# auto memory の棚卸し

auto memory を実測・鮮度検証・自明化チェック・ユーザー合意のもとで整理し、必要な記憶だけを簡潔に保つ。
引数にプロジェクトパスまたは memory ディレクトリパスが渡された場合はそれを対象とし、無ければ現在のプロジェクトを対象とする。

## 前提と承認レベル

- 毎セッション読まれるのは `MEMORY.md` のみ（先頭 200 行 / 25KB で切り捨て）。棚卸しの主眼は目次を正確かつ短く保ち、残す本文も冗長を排することにある
- `~/.claude/projects/` は git 管理外のため、ファイルは削除せず `_archive/` へ退避する
- 本文中の `[[name]]` はファイル名ではなく frontmatter の `name:` を参照する
- 起動時リマインドは `.claude/hooks/memory-inventory-reminder.sh`（Phase 6 で更新する `.inventory-state.md` の更新時刻を参照）に委ね、過剰な再圧縮は行わない

| 操作 | 承認 | 理由 |
|:--|:--|:--|
| 目次の圧縮（詳細をトピック側へ移動） | 不要（事前共有のみ） | 情報が失われない |
| 事実誤りの修正（実体・`gh` 等で検証済み） | 不要（事前共有のみ） | 根拠が客観的 |
| `name:` をファイル名へ揃え `[[ ]]` を張り替える | 不要（事前共有のみ） | 機械的で情報が失われない |
| `_archive/` への退避 | カテゴリ単位で確認 | 可逆 |
| ファイルの統合・本文の削除や圧縮・dotfiles 昇格 | **必須** | 不可逆または公開リポ・他端末へ波及する |

## Phase 0 — バックアップと前回状態

memory ディレクトリを特定してバックアップを取る（特定に失敗した場合は推測せずユーザーへパスを確認する）。

```bash
/usr/bin/env python3 -B <SKILL_DIR>/scripts/inventory.py backup \
  [--dest-dir "<dir>"] \
  [--project "<path>" | --mem-dir "<path>"]
```

`--dest-dir` を省略すると一時ディレクトリへ退避する。出力に `.inventory-state.md` が含まれる場合、前回実行日と「解除条件つきで見送った項目」を確認し、見送り項目は Phase 2 で最優先に検証する。

## Phase 1 — 実測

```bash
/usr/bin/env python3 -B <SKILL_DIR>/scripts/inventory.py measure \
  [--project "<path>" | --mem-dir "<path>"]
```

確認する指標: `MEMORY.md` の上限使用率、トピック件数、`type` 分布、薄いファイル（本文 5 行以下かつ 500B 以下）、孤児、`name:` 不一致、リンク切れ、未解決の `[[name]]`（スキル名など memory 以外の記法は除外して読む）、150 字超のフック行。

## Phase 2 — 鮮度・自明化検証

全トピックファイルのメタ情報と本文を取得し、外部の事実・現行モデルの前提と突き合わせる（出力が大きい場合は退避ファイルを読む）。

```bash
/usr/bin/env python3 -B <SKILL_DIR>/scripts/inventory.py dump \
  [--project "<path>" | --mem-dir "<path>"]
```

検証観点:
- **実体・状態**: ファイル・関数・フラグの実在（`ls` / `find` / `grep`）、PR / issue の状態（`gh pr/issue view`）、「◯◯まで注意」「未定」「マージ前」型の解除有無、相対日付の絶対日付化
- **指示書との重複・矛盾**: グローバル `AGENTS.md` / `CLAUDE.md` / `.claude/rules/` やプロジェクト指示書・skill と照合する（矛盾があれば指示書側の誤りも疑う）
- **AI 進化による自明化**: 現行モデルやハーネス標準で自明になった一般知識・ツール挙動、旧モデル固有の回避策が残っていないか確認する
- **本文の冗長・語彙汚染**: 残すファイルでも、前置き・過去の作業ログ・同じ内容の反復・過剰強調や不自然な造語で肥大化していないか確認する

検証できなかった項目は「未検証」と明記し、検証済みと混ぜない。

## Phase 3 — 提案の組み立て

ファイル単位ではなく、判断の性質ごとにカテゴリへまとめる。

- **事実誤り** — 検証で誤りが確定（承認不要だが必ず事前共有）
- **役割終了・再取得可能** — 完了作業・決着 issue・期日切れ・コード/git/指示書を見れば分かるだけの記録 → 退避候補
- **AI 進化で自明化** — 現行モデル・ハーネス標準で不要になった記述・旧モデル向け回避策 → 退避候補
- **冗長・語彙汚染・目次の肥大** — 150 字超のフック行、または残す本文の前置き・作業ログ・反復・過剰強調や造語 → 圧縮・整理候補
- **統合** — 同じ話題の複数ファイル（近接クラスタ）や単独不要な薄いファイル → 統合候補
- **rules 向き** — プロジェクト非依存で今後も踏む固有の罠・好み → 昇格候補（共通なら dotfiles の `AGENTS.md`、Claude 固有なら `.claude/rules/`。既存と重複すれば昇格しない）

判断の線引き:
- **残す基準**: AI が推論できずコード等からも引き直せないもの（ユーザーの好み、判断の経緯、環境固有の実測の罠）だけ残す
- **`project` 型**: 恒久的な技術知見は `project` のままでよい（`reference` は外部リソースへのポインタ専用）

## Phase 4 — 合意

全ラウンドの合意がそろうまで Phase 5 へ進まない。

- **事前共有**: 最初のラウンド前に、承認不要の修正内容と各カテゴリの根拠をチャット本文へ簡潔に出す
- **質問の粒度**: 質問ツール（無い環境ではチャットで番号選択）で 1 ラウンド最大 4 問・カテゴリごとに 1 問・選択肢 2〜4 個で聞く。カテゴリ横断の「まとめて全部」は避け、4 カテゴリ超なら目次に関わるものを優先してラウンドを分ける
- **選択肢の組み方**: 基本は「一括で実行」「個別に見る」「やらない」（一部のみ推奨なら「推奨の N 件だけ実行」）。推奨を先頭に `(Recommended)` を付け、説明欄に対象件数と代表ファイル名を書く
- **個別確認**: 「個別に見る」が選ばれたカテゴリは、次ラウンドで 1 件ごとの推奨を提示して確認する

## Phase 5 — 反映

合意された範囲のみ、次の順序で実行する（目次は最後に 1 回だけ書き直す）。

1. **事実修正・相対日付の変換**: 相対日付を絶対日付へ直す（基準不明なら報告へ明記）
2. **統合・退避・圧縮・昇格**:
   - **退避**: 恒久的な教訓を生き残る側へ移してから実行し、他ファイルの `[[name]]` を吸収先へ張り替える（無ければ外す）:
     ```bash
     /usr/bin/env python3 -B <SKILL_DIR>/scripts/inventory.py archive \
       [--project "<path>" | --mem-dir "<path>"] <file.md> [...]
     ```
   - **統合**: 厚い側を残し、薄い側を見出し付きセクションとして末尾へ移してから薄い側を退避する
   - **本文の削除・圧縮**: 削る箇所を `_archive/<name>_log_<YYYY-MM-DD>.md` へ切り出してから本体を簡潔に書き直す
   - **dotfiles 昇格**: リポジトリ実体側を編集し、`AGENTS.md` 更新時は `.codex/build-agents.sh` を実行する（編集ファイルだけ明示ステージ）。昇格済みの memory は退避する
3. **`name:` の統一と `[[ ]]` の張り替え**: `name:` をファイル名（`.md` 除く）へ揃え、リンク先を更新する
4. **目次の書き直し（`MEMORY.md`）**:
   - 1 件 1 行・150 字以内・`- [Title](file.md) — 一行フック` とし、要約ではなく「開くべき条件」を書く（近い話題は発動条件で書き分ける）
   - 30 件を超えたら場面ごとの見出し（`## 環境・ツール` 等）で束ね、重要な孤児は追加する
   - ファイル書き込みツール（またはシェルの `>|`）で書き直す
5. **再計測**: `inventory.py measure` を再実行し、上限以内・リンク切れ/孤児/`name:` 不一致が無いことを確認する

## Phase 6 — 記録と報告

Phase 5 の全編集を終えてから（リマインダーフックが更新時刻を基準にするため）、`$MEM_DIR/.inventory-state.md` を更新する。

```markdown
最終実行: YYYY-MM-DD
MEMORY.md: <行数> 行 / <バイト数> bytes

## 解除条件つきで見送った項目
- <file>.md — <解除条件>（例: PROJ-1234 がマージされたら退避する）
```

最後にチャットで次を報告する:
- 触ったファイル数と操作の内訳（修正 / 圧縮 / 退避 / 統合 / 昇格）
- `MEMORY.md` の before / after（行数・バイト数・上限使用率）
- 見送った項目（解除条件があるものは `.inventory-state.md` にも記載）
- 未検証のまま残した項目
- バックアップのパス
