# セッションの引き継ぎ

現在のセッションから、次セッションが同じ判断を再現でき、新しい局面でも同じ基準で動ける引き継ぎを作成する。
引数がある場合は、それを次セッションの主題として引き継ぎ全体をその作業へ寄せる。

## 手順

1. セッションを振り返り、出力項目を埋める材料を集める
2. 目的・背景がセッション中に語られていなければ、出力前に質問ツール（またはチャット）でユーザーへ確認する（推測で埋めない。確認するのは目的だけ）
3. 秘匿情報を除き、引き継ぎ本文をチャットへ出力する
4. 環境を問わず、`~/.claude/handoffs/<YYYYMMDD-HHMM>-<主題>.md` にも同一の本文をファイル書き込みツールで保存する（日時は `date +%Y%m%d-%H%M`、ファイル名に使えない記号は `-` に置換。リポジトリ内や一時作業領域には書かない）
5. Herdr または T3 Code 内なら、保存したファイルを使って次セッションを自動起動する（下記「次セッションの自動起動」）。どちらでもなければここで終える
6. auto memory がある環境なら、恒久化すべき知見の保存を提案する（下記「memory への仕分け」）

## 書き方の基準

- **要約にしない**: 時系列の作業ログや捨てた試行の詳細は落とす。ただし、方針転換の理由になった事実（「A を進めたが X が判明して B にした」の X）は再提案を防ぐために残す
- **理由と基準を残す**: 決定・見送った選択肢には理由を添え、決定の背後にあるユーザーの好みや制約も書く
- **詳細はポインタで済ませる**: PR・仕様書・commit・チケットに残っている内容は転記せず参照先だけ示す
- **長さの上限は設けない**: 必要な判断材料を削らない
- **秘匿情報を載せない**: API キー・トークン・パスワード・個人情報・顧客データは除き、必要なら値ではなく在り処を書く（例: 1Password の項目名）。除去した旨は続行に影響するときだけ書く

## 出力フォーマット

チャット出力と `~/.claude/handoffs/` のファイルで同じ本文を使う。1行目に待機指示を必ず置く（次セッションが残タスクを見て勝手に着手するのを防ぐため）。

```markdown
前のセッションからの引き継ぎです。内容を把握し、参照先に使う skill があれば読み込んだうえで、ユーザーの指示を待ってください（作業や編集にはまだ着手しないでください）。

## 引き継ぎ: <主題>

### 目的・背景
- ...

### 現在の状態
- ...

### 残タスク
1. 【自分 / ユーザー / 未定】...（目的: ...）

### 下した判断と理由
- ...

### ユーザーの好み・制約
- ...

### 未解決の疑問・仮説
- ...
```

### 必須セクション（常に出す）

該当がない項目は「なし」と明記する（書き忘れと区別するため）。

1. **目的・背景** — なぜやるか、何が達成されたら終わりか、きっかけ
2. **現在の状態** — どこまで終わったか、次に最初に把握すべき事実
3. **残タスク** — 担当（自分 / ユーザー / 未定）、着手順（ある場合）、各タスクの目的を一言添える
4. **下した判断と理由** — 採用した方針と見送った選択肢、それぞれの理由（環境やツールの罠は「詰まった箇所」へ分け、重複させない）
5. **ユーザーの好み・制約** — セッション中に分かった判断基準、こだわり、NG 事項、優先順位
6. **未解決の疑問・仮説** — 未検証の仮説、迷っている点、崩れると方針が変わる前提

### 条件付きセクション（該当時のみ出す）

セッション中に該当がなければ、見出しごと省略する（「なし」も書かない）。必要性はセッション内容から自分で判定し、ユーザーには聞かない。

| 条件 | セクション | 書く内容 |
|---|---|---|
| 同じ作業で再発しうる罠に遭遇した | **詰まった箇所と回避方法** | 罠と回避策をセットで書く（開発: サンドボックス拒否・エイリアス・自動生成差分／調査: データ欠損・前提条件／対人: 相手の制約・効かなかった提案） |
| git 管理下で変更・commit・push・PR があった | **ブランチ・PR** | ブランチ名、base、HEAD、PR URL、作業ツリーの状態（未コミット差分の有無） |
| テスト・lint・静的検査を実行した | **検証コマンド** | そのまま再実行できるコマンドと結果 |
| 引き継ぐ参照先がある | **参照先** | チケット、ドキュメント、URL、次セッションで使う skill |

## 次セッションの自動起動

該当する環境でのみ行う。元のセッション・pane は閉じず、`~/.claude/handoffs/` の過去ファイルも消さない。途中で失敗したら失敗箇所と出力を報告して止める（チャット出力を手動で貼れば続行できる）。

### Herdr

`test "${HERDR_ENV:-}" = 1` が成り立つときだけ行う。`herdr` の詳細なコマンド仕様は `herdr` skill と `herdr --help` に従う。

1. サンドボックス外で `herdr pane layout --pane "$HERDR_PANE_ID"` を実行して分割方向を決め（横に広ければ `right`、縦に長いか狭ければ `down`）、同じサンドボックス外で起動スクリプトを実行する:
   ```bash
   ~/.claude/skills/session-handoff/scripts/launch-herdr.sh \
     "$HOME/.claude/handoffs/<ファイル名>" \
     --kind <実行中のエージェント種別> \
     --direction <right|down>
   ```
   `<実行中のエージェント種別>` は `herdr agent start --kind` の値（例: Claude Code なら `claude`、Codex なら `codex`、Gemini なら `gemini`）。省略時は現在の pane から自動取得を試みる。
2. 末尾の `agent read` 出力で次セッションが指示待ちになったことを確認し、pane ID・エージェント名・ファイルパスを報告する
3. `agent prompt` が `timeout` や `agent_prompt_stalled` を返しても届いている可能性があるため再送せず、`agent read` の出力で確認する

### T3 Code

以下のいずれかを満たすときに行う（仕様の正本: https://github.com/pingdotgg/t3code/blob/main/docs/user/outside-agents.md）。

- `CLAUDE_CODE_ENTRYPOINT=t3-code`
- `T3_ACP_MCP_NODE` が設定されている
- `t3-code` MCP server（`t3_thread_launch` 等）が利用できる

1. MCP ツール `t3_thread_launch` が使える場合は、次を渡して呼ぶ（完了は待たず、返ってきた `threadId`・リンク・ファイルパスを報告する）:
   - `title`: 短く時刻付き（例: `handoff 1530 <主題>`）
   - `message`: 書き出した引き継ぎファイルの内容（上限 120k 文字）
   - `projectId`: 渡さない（現在のプロジェクトを引き継ぐ）
2. `t3_thread_launch` が使えない場合は CLI で起動する（T3 Code 起動中かつ `t3` が PATH にある前提）:
   ```bash
   HANDOFF_FILE="$HOME/.claude/handoffs/<書き出したファイル名>" TITLE="<title>" bash <<'SCRIPT'
   set -eu
   t3 thread start . - --title "$TITLE" < "$HANDOFF_FILE"
   SCRIPT
   ```

使わない手段:
- `fork`・`/compact`・`delegate_task`: 今のセッションの文脈を持ち越すため
- prompt の deep link: 長い引き継ぎを URL に載せることになるため

## memory への仕分け

auto memory（`~/.claude/projects/<project>/memory/` 等）がある環境では、引き継ぎ内容のうち今後も再発する知見を memory へ保存する候補として提案する。

- **memory 候補**: 環境・ツール・規約に起因して再発する罠、タスクを越えて変わらないユーザーの好み・判断基準
- **引き継ぎのみ**: このタスク・この時点に限った事情

提案前に既存 memory との重複を確認し、保存はユーザーの承認後に行う。
