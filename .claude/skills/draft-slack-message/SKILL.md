# Slack メッセージの作成

本人が書いたと読める文面を作る。文体は毎回、本人の過去投稿から取る。

## モード

どちらのモードでも**送信はしない**。

| 依頼 | モード |
|---|---|
| 「メッセージを作って」「返信を考えて」など、下書きの指示がない | 文面をチャットへ出して終了 |
| 「〇〇に下書きして」など、チャンネル・スレッドへの下書きを頼まれた | チャットで承認を得てから下書きを作成 |

Slack MCP ツールが利用できない環境では、文面作成のみ行いチャットへ出力する。

## 手順

1. **投稿先を読む**
   - スレッド返信: スレッド全体を読み、相手が使う呼び名（バッチ名・機能名・チケット名）を控えて表記を揃える
   - 新規投稿: チャンネルの説明とトピックを読み、投稿内容がそのチャンネルに合うか確認する（合わなければ伝える）
   - チャンネル・スレッドが読めない、または見つからない場合は、投稿先 URL・チャンネル名を確認する
2. **本人のユーザー ID を取る**
   - `slack_read_user_profile` を引数なしで呼ぶ（ID はスキルに固定しない）
3. **本人の過去投稿を 5〜10 件読む**
   - 次の優先順で探し、足りなければ広げる:
     1. 同じスレッド・同じチャンネル
     2. 同じ相手への投稿（`with:` や相手へのメンションを含む投稿）
     3. 同じ種類の投稿（進捗共有・確認・依頼・レビュー依頼など）
   - 非公開チャンネル・DM が投稿先のときは `slack_search_public_and_private` を使う（本人の過去投稿参照は依頼に含まれるため、都度の同意確認は不要）
   - 過去投稿が 0 件または少ない場合は、共通ルールと投稿先チャンネルの既存投稿の雰囲気に合わせる
4. **文体を抽出する**
   - 敬体か常体か（相手・チャンネルで変わる）
   - 書き出し・締め、メンション・cc の付け方
   - よく使う絵文字・定型表現
   - 構成（結論先出しか経緯先出しか）、長さ、リンクの置き方
5. **文面を書く**
   - 手順 4 の文体に、`AGENTS.md`（I/O Rules → Posts as the user: 文末「。」なし・改行区切り・表禁止）と次の Slack 制約を重ねる:
     - 質問への返信は、答えを最初の 1〜2 行に書き、理由や補足はその後に置く
     - 箇条書きは `- ` を使い、前後に空行を入れる（空行がないと次行が最終項目に連結する）
     - 項目ごとに説明や注意があるときは、2 スペースのインデントで入れ子にする。親は項目名だけ、子に説明、孫に注意や補足を書く
     - 強調・太字は過去投稿で使っていなければ使わない
     - AI っぽい表現や不自然な業界用語を避け、1 通の中で同一対象の語を揃える
     - 依頼にない話題を足さない。根拠の PR・チケット・Notion があればリンクを添える
6. **チャットへ提示する**
   - 文面と、文体参照元の投稿リンク 1〜2 件を添える
   - メンションやグループ宛先を推測した場合は根拠も明記する
7. **下書き作成（下書きモード・承認後のみ）**
   - 承認を得てから `slack_send_message_draft` で下書きを作成する（スレッド返信は `thread_ts` を指定）
   - 作成後にチャンネルのリンクを伝える

## 下書き API の制約

- 作成済みの下書きは API で更新できない。修正時は差し替え文面を渡し、Slack 画面上で編集してもらう
- 同一チャンネルに 2 件目の下書きは作れない（`attached_draft_exists`）。作り直す場合は既存下書きを削除してもらってから再作成する
