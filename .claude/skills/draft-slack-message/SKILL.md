# Slack メッセージの作成

本人が自分で書いたと読める文面を作る。文体は毎回、本人の過去の投稿から取る。

## モード

依頼の言い方で決める。

| 依頼 | モード |
|------|--------|
| 「メッセージを作って」「返信を考えて」など、投稿先の指示がない | 文面をチャットに出して終わる |
| 「〇〇に下書きして」など、チャンネルやスレッドへの下書きを頼まれた | 文面をチャットで確定させてから下書きを作る |

どちらのモードでも送信はしない。

## 手順

1. 投稿先を読む
   - スレッドへの返信なら、スレッド全体を読む。相手が使っている呼び名（バッチ名、機能名、チケット名）を控え、文面でもその表記に揃える
   - 新規投稿なら、チャンネルの説明とトピックを読み、投稿の種類がそのチャンネルに合うか確かめる。合わなければ伝える
2. 本人のユーザー ID を取る（`slack_read_user_profile` を引数なしで呼ぶ）。ID はスキルに書かず、毎回取る
3. 本人の過去の投稿を5〜10件読む。次の順で探し、足りなければ広げる
   - 同じスレッド、同じチャンネル
   - 同じ相手への投稿（`with:` や相手へのメンションを含む投稿）
   - 同じ種類の投稿（進捗共有、確認、依頼、レビュー依頼など、キーワードで探す）

   非公開チャンネルや DM が投稿先のときは `slack_search_public_and_private` を使う。この依頼は本人の投稿を読むことを含むので、改めて同意は取らない
4. 読んだ投稿から次を取り出す
   - 敬体か常体か（相手やチャンネルで変わることが多い）
   - 書き出し、締め、宛先メンションや cc の付け方
   - よく使う絵文字や定型の言い回し
   - 構成（結論が先か、きっかけが先か）、長さ、リンクの置き方
5. 文面を書く。手順4の文体に、次の共通ルールを重ねる
   - 文末に「。」を付けない。文を区切るときは改行する
   - 箇条書きは `- ` で書き、前後に空行を入れる。入れ子にしない（空行がないと次の行が最後の項目につながり、入れ子は親の行にくっつく）
   - 表を使わない
   - 強調や太字は、過去の投稿で使っていなければ使わない
   - AI っぽい語や業界用語を避け、平易に書く。1通の中で同じものは同じ言葉で書く
   - 依頼に書かれていない話題を足さない。根拠になる PR、チケット、Notion ページがあればリンクを置く
6. 文面をチャットに出す。文体を取った投稿を1〜2件、リンクで添える。メンションやグループの宛先を推測で入れたときは、その根拠も示す
7. 下書きモードなら、OK をもらってから `slack_send_message_draft` を作る。スレッドなら `thread_ts` を渡す。作った後はチャンネルのリンクを伝える

## 下書きの制約

- 作った下書きは API で書き換えられない。直すときは差し替えの文面を渡し、本人に Slack の画面で直してもらう
- 同じチャンネルに2つ目は作れない（`attached_draft_exists`）。作り直すときは、本人に既存の下書きを消してもらってから作る
