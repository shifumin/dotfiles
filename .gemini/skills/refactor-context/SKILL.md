# コンテキスト文書の診断と再設計

Skill・Memory・Rule・指示書をゼロベースで見直し、元の意図や安全策を落とさずに、汚染語彙のない自然な表現・一貫した構造・壊れにくい手順へ作り直す。

対象は引数（スキル名・ファイルパス・ディレクトリパス）または会話で指定されたもの。単一ファイルだけでなく、ディレクトリ単位の横断精査にも対応する。

## 対象種別

| 種別 | 主な対象 |
|---|---|
| Skill / Command | `SKILL.md`, `references/`, `scripts/`, `.claude/commands/*.md` |
| Rule / 指示書 | `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, `.claude/rules/*.md`, `.codex/AGENTS.codex.md` |
| Memory | `~/.claude/projects/<project>/memory/`（`MEMORY.md`・トピックファイル群） |

## 手順

1. **対象と周辺を読む**: 正本を特定し、関連ファイルまでまとめて確認する（下記「調査で集める情報」）
2. **改善ポイントを報告する**: 4つの観点で問題点を整理し、設計判断が分かれる点（2〜3点以内）だけユーザーへ確認する（すでに「お任せ」「全部直して」と指示があれば確認を省いて進む）
3. **ゼロベースで書き直す**: 継ぎ足し編集ではなく、対象種別の安全策を守りながら全体を一貫した構成へ組み直す
4. **検証する**: 対象種別に応じた構文・動作テスト、同期チェック、意図の漏れ確認を行う
5. **結果と差分を報告する**: コミット・push はユーザーの指示があってから行う

## 調査で集める情報

編集前に次を確認し、机上の空論や意図の取りこぼしを防ぐ。

- **正本と構成**: symlink を辿って正本パスを特定し、対象と付属ファイル（`scripts/`, `references/` 等）をすべて読む。サードパーティ（vendored）のファイルは直接編集せず提案に留める
- **変更履歴**: git 管理下なら直近の git log を確認し、過去の不具合対応や継ぎ足された意図を把握する
- **周辺ルールと重複先**: 関連するスキル・`AGENTS.md`・`CLAUDE.md`・`.claude/rules/`・`MEMORY.md` を確認し、重複・矛盾・記述規約（記述言語、公開リポ制約）を把握する
- **実物とツール仕様**: 対象 CLI の `--help` や過去の出力実例・実データを確認し、実運用でのズレやバグを拾う

## 診断の4観点

### 1. 語彙汚染と表現の掃除
特に毎セッション常時注入される Rule・指示書・`MEMORY.md` は最優先で確認する。
- **不自然な造語・抽象ラベル**: 文脈なしでは意味がぼやける造語や抽象表現（例: 「共通骨格」「追加層」「判断に効く」「理由の由来」）を具体的な言葉へ直す
- **過剰な強調・脅し・演説調**: 「絶対禁止」「最悪」「ここが本体」のような感情的・劇的な修飾語を削り、事実と条件だけを淡々と書く
- **行動を変えないメタ語り・日記**: 「〜は結果であって目的は〜」「2026-XX の件で〜」など、現在の振る舞いを変えない解説や過去の作業ログを落とす
- **不自然な翻訳調・文体混在**: 常体／敬体／である調の混在、指示書に不要な口調、不自然なカタカナ直訳を整える
- **記述言語の遵守**: 英語で書かれているファイル（例: `dotfiles/AGENTS.md` や `.claude/rules/*.md`）は英語のまま、冗長・曖昧な表現を簡潔に整える

### 2. 構造・重複・参照の整理
- **重複の削除**: 1ファイル内、および `AGENTS.md` / `.claude/rules/` / `SKILL.md` / `MEMORY.md` をまたいだ同じルールの反復を削る
- **他ファイル仕様のコピー排除**: 別スキルやフックの数値（タイムアウト・閾値・回数）やコマンド仕様を再掲せず、正本への参照へ置き換える
- **章立ての順序**: 実行手順や重要ルールが末尾に埋もれていないか、上から順に読める並びへ組み替える
- **入口の圧縮**: Skill の `description` や `MEMORY.md` の 1 行フックがコンテキスト予算を圧迫していないか確認する

### 3. 仕様の穴・スクリプトのバグと責務分離
主に Skill・Command・付属スクリプトが対象。
- **仕様の曖昧さ**: 出力フォーマット未定義、空・該当なし時の扱い、似た項目間の境界、分岐条件の漏れ、複数出力先間の不一致を潰す
- **責務分離**: 長大な `bash` ブロックや特定環境専用の手順が本文を肥大化させていれば、`scripts/` や `references/` へ切り出す
- **シェル・スクリプト点検**:
  - リトライ上限到達時に exit 0 で素通りしないか
  - `set -u` 下で未定義になり得る環境変数（`$TMPDIR` 等）を使っていないか
  - 固定一時ファイル（`noclobber` や並行実行で壊れる）を変数受けや `mktemp` にできないか
  - 連打や同時間帯で衝突する名前（秒なしの時刻など）になっていないか
  - 失敗時に調査用の識別子や直前出力が失われないか
  - macOS `/bin/bash`（3.2）や zsh 固有の罠（未クォートの `@{u}`、`rm`/`cp`/`mv` の `-i` エイリアス等）を踏んでいないか

### 4. 環境・マルチエージェント整合性
- 複数エージェントで共有されるファイルに、特定エージェント固有のツール名直書き（`AskUserQuestion`, `Write` 等）や固定値（`--kind claude`、単一環境変数での判定、特定ツール専用フック前提の断定）が混ざっていないか
- 単一エージェント専用のファイルなら、その前提が明確か

## 対象種別ごとの安全策と検証

- **共通**:
  - 既存の判断基準・エッジケース対策・安全策（削除禁止、再送禁止、確認必須など）を落とさない
  - 公開リポジトリ（`dotfiles` 等）では実名・固有ホームパス・社内情報・機密を書かない（`~`・`$HOME`・プレースホルダを使う）
- **Memory**:
  - git 管理外のため、編集前に必ず一時ディレクトリ（`${TMPDIR:-/tmp}`）へ対象ディレクトリをバックアップする
  - 鮮度検証や `_archive/` 退避の棚卸しは `memory-inventory` に任せ、本スキルは語彙汚染・重複・構造のリライトに集中する
  - 編集後に `MEMORY.md` の上限（200行 / 25KB）とリンク整合性を確認する
- **Rule / 指示書**:
  - 生成物があるリポジトリでは再生成とドリフト検証を行う（例: `dotfiles/AGENTS.md` 更新時は `.codex/build-agents.sh` と `--check`）
- **Skill / スクリプト**:
  - 新設・変更したスクリプトには `chmod +x` を付け、構文チェック（シェルは `bash -n`、Python は `__pycache__` を作らない `python3 -B -c "import ast, pathlib; ..."`）と、モックを使った正常系・リトライ・上限超過・異常系のテストを行う
  - スキル同期スクリプトがあるリポジトリでは検証する（例: `.agents/sync-skills.sh --check`）

## Git 反映時（依頼された場合のみ）

1. 別件の未コミット変更を巻き込まないよう、対象ファイルだけを明示的に `git add` する
2. push 前に `git fetch` でリモートの先行コミットを確認する。同じファイルに先行変更があれば上書きせず統合してからコミットする
3. push 後に `HEAD` と上流ブランチ（`'@{u}'`）の一致を確認する
